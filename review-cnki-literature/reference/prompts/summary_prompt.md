```markdown

{用 3-5 句话概括文献的主要研究思路/方法论，回答"这篇文献在研究什么、怎么研究的"}

{数据来源（与头部"数据来源"字段一致，可补充细节）、样本区间、研究市场/对象（如中国 A 股、沪深上市公司、某行业企业等）}

{完整、客观抄录核心模型/方法的数学定义/函数形式，保留原始公式符号（如 $LaTeX$）}

{如果文献没有给出明确公式，则描述方法/变量构造的逻辑步骤}

{精炼总结方法背后的理论直觉、经济学/管理学机制解释，1-3 句话}

{该文献相对于已有文献的差异化贡献，1-2 句}

## 关键原则
1. 只关心思路，完全不关心实证结果数字：所有回归系数、t 值、显著性星号、R² 等一律忽略
2. 模型与方法公式必须完整抄录
3. 理论解释要精炼
4. 异质性与边界条件要具体，不要写泛泛的话
5. 不要用代码块包裹输出
6. **公式渲染规则（极重要）**：所有数学公式必须使用 LaTeX 块公式语法 `$$...$$` 包裹（每个独立公式一个 $$...$$ 块），以便在 Markdown 中正常渲染。变量名中的下划线**绝对不要**用反斜杠转义为 `\_`，直接写 `_`（如 `PV_corr_avg` 而不是 `PV\_corr\_avg`）。多个公式之间用普通文字（如「其中：」）分隔，每段公式都单独 `$$...$$` 包裹。例如：
   $$CPV = \frac{{X - \text{{mean}}(X)}}{{\text{{std}}(X)}}$$
   其中：
   $$X = \text{{Corr}}(P, V)$$
   注：上面例子里的 `{{` `}}` 是 Python `.format()` 转义写法，真正喂给 LLM 的 prompt 里应该是单层 `{` `}`。

7. **严禁任何形式的行内 `$x$`（极重要！踩坑教训）**：
   - **整篇摘要里只允许 `$$...$$` 块公式，绝对不要使用 `$x$` 行内公式**，包括变量名引用、希腊字母、上下标等
   - 变量注释、其中说明、文字描述一律用**纯文字**写变量名，不要包 `$`
   - 正确写法：
     ```
     $$PV_corr = \text{{Corr}}(P, V)$$
     其中 P 为价格序列，V 为成交量序列；P_t 表示第 t 日的分钟收盘价。
     ```
   - 错误写法 1（块内含 `$P$`，KaTeX 直接报错）：
     ```
     $$PV_corr = \text{{Corr}}(P, V)，其中 $P$ 为价格序列$$
     ```
   - 错误写法 2（块外用行内 `$P_t$`，紧贴中文，渲染失败）：
     ```
     $$PV_corr = \text{{Corr}}(P, V)$$
     其中 $P_t$ 为第 $t$ 日的价格序列，$V_t$ 为第 $t$ 日的成交量。
     ```
   - **为什么完全禁用行内 `$x$`**：行内 `$...$` 在不同 Markdown 渲染器下行为差异巨大——GitHub 要求 `$` 两侧必须是空白，KaTeX 严格模式拒绝 `$P\_corr$` 这种含 `\_` 的写法，`$0^\circ\text{{至}}90^\circ$` 这种中外文混合也容易触发解析错误。统一禁用是唯一可靠的方案。
   - `\text{{}}` 内部也不要出现 `$` 或 `\$`
   - `$$` 必须紧贴公式内容写，不要写成 `$ $`（中间不要有空格）
   - **每个 `$$...$$` 块独占一段，前后必须有空行**：相邻的两个 `$$f1$$` 和 `$$f2$$` 之间不能只隔一个换行，必须有空行分隔，否则 KaTeX/CommonMark 会把它们合并成一个 math 上下文导致解析失败。
     正确写法：
     ```
     $$f1 = ...$$

     $$f2 = ...$$
     ```
     错误写法（紧挨）：
     ```
     $$f1 = ...$$
     $$f2 = ...$$
     ```
   - 不要在 `$$...$$` 块尾加 Markdown 换行标记 `  `（两个空格）

---
文献标题：{title}

作者：{authors}
发表年份：{year}
页数：{page_count}

文献全文：
{full_text}
```

## 摘要提取的核心原则

> Prompt 模板内的"关键原则"已涵盖这些规则。此处仅补充产生这些规则的踩坑背景。

1. **不要实证结果数字** — 不同文献的样本区间/模型设定差异太大，系数与显著性数字不可比。
2. **方法公式必须完整抄录** — 后续复现的唯一依据。
3. **公式用 `$$...$$` 块** — 踩坑：第一次跑出的公式在 Markdown 里全是裸文本。
4. **严禁行内 `$x$`** — 踩坑：LLM 本能混用行内公式，KaTeX 报 `Can't use function '$' in math mode`。后处理 `sanitize_dollars` 是 0 成本兜底。

## 关键代码片段

**输入截断 + 输出后处理**（每篇全文截断 30000 字符；LLM 常见三类污染需清理）：

```python
import re

full_text = item['full_text'][:30000]  # 截断避免超 token 限制

# --- 对 LLM 返回的 content 做后处理 ---
# 1. 去掉代码块包裹
if content.startswith('```'):
    content = re.sub(r'^```\w*\n?', '', content)
    content = re.sub(r'\n?```$', '', content)
# 2. 去掉 prompt 泄漏（LLM 有时会重复"关键原则"段落）
content = re.split(r'\n## 关键原则', content)[0]
# 3. 清理所有 $ 残留：块内的 + 块外行内 $x$ 的（KaTeX "Can't use function '$' in math mode" 的真正根因）
content = sanitize_dollars(content)


def sanitize_dollars(text: str) -> str:
    """三层清理（解决 KaTeX "Can't use function '$' in math mode" 的所有变体）：

    1. $$...$$ 块内的残留 $ 全部去掉
    2. 块外的所有行内 $x$ 也去掉 $，变成纯文字
       —— 行内 $...$ 在不同 Markdown 渲染器下兼容性极差：
          GitHub 要求 $ 两侧必须空白，紧贴中文会失败；
          KaTeX 严格模式拒绝 $P\\_corr$ 含 \\_ 的写法；
          中外文混合 $0^\\circ\\text{至}90^\\circ$ 也会报错。
    3. 规范化块公式段落：每个 $$...$$ 必须独占一段，前后都有空行
       —— CommonMark/GFM + KaTeX 规则：相邻的两个 $$...$$ 块若没有空行分隔，
          会被解析器合并成单个 math 上下文，中间的 $$ 边界变成非法的 $ 字符。
          LLM 输出常见 `$$f1$$\\n$$f2$$` 紧挨写法 —— 必须强制插空行。
          同时把行尾的 Markdown 换行标记 `  ` (两空格) 去掉。
    """
    # Step 1+2: 用占位符保护合法的 $$...$$ 块，清掉块内的 $；然后去掉块外所有 $
    placeholders = []
    def stash(m):
        body = m.group(1)
        if '$' in body:
            body = body.replace('$', '')
        placeholders.append(f'$${body}$$')
        return f'\x00BLOCK{len(placeholders)-1}\x00'
    text = re.sub(r'\$\$(.*?)\$\$', stash, text, flags=re.DOTALL)
    text = text.replace('$', '')
    text = re.sub(r'\x00BLOCK(\d+)\x00', lambda m: placeholders[int(m.group(1))], text)

    # Step 3: 规范化块公式段落
    # 3a. 去掉块尾紧跟的 Markdown 行尾两空格标记
    text = re.sub(r'(\$\$)  +(?=\n|$)', r'\1', text)
    # 3b. 给每个 $$...$$ 块前后强制加空行（用占位符避免重复包裹）
    def wrap(m):
        return f'\n\n{m.group(0)}\n\n'
    text = re.sub(r'\$\$.*?\$\$', wrap, text, flags=re.DOTALL)
    # 3c. 合并多余的连续空行
    text = re.sub(r'\n{3,}', '\n\n', text)
    return text.strip() + '\n'
```

**为什么必须做这一步**：LLM 看到 prompt 里说"公式用 `$$...$$`"会照办，但变量注释时本能切换回行内 `$x$`，结果两套语法在同一段里互相污染。**在原券商研报版流程中实测一个 53 篇的项目，0 篇有块内 `$`，但拼装出的 thematic_summary.md 里有 78 个块外残留行内 `$`**——这才是 KaTeX 报错的真正主因。即使 prompt 已经明确禁止，仍有约 30%-50% 的 LLM 输出会犯这个错（变量注释是它的本能写法）。后处理是 0 成本的兜底，必须加。
