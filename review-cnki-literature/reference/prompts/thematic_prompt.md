## 主题归纳 Prompt 模板（注意：只让 LLM 产出 JSON 分组，不让 LLM 写"涉及文献"列表）

```
你是一名学术文献综述助手。以下是多篇与「{用户的预设主题}」主题相关的文献摘要。

请将这些文献按照**研究思路的相似性**归纳为若干主题类别，并产出 JSON 格式的分组结果。

每个主题包含：
- name: 通俗白话的主题名
- core_idea: 该类文献的共性思路描述（3-5 句白话）
- econ: 该主题下方法/模型的核心理论逻辑
- interaction: 该主题下各篇提到的异质性表现与适用边界
- members: 归属此主题的**代表性**文献文件名列表（去重后，详见下方"同团队重复发表去重"原则）
- duplicate_groups: 字典 `{{代表作文件名: [同团队重复发表版本文件名, ...]}}`，把学位论文/期刊版/中英文双发等同团队重复发表版本归到代表作下
- flagship: **从 members 中选一篇最具代表性的文献文件名**（开山之作 / 方法定义最完整 / 被后续文献引用最多 / 该主题最经典实现），代码会从该篇的"模型与方法构建"段抽取公式作为该主题的代表性公式

输出严格遵循以下 JSON 格式（不要包代码块，不要加任何解释）：

{{
  "themes": [
    {{
      "name": "...",
      "core_idea": "...",
      "econ": "...",
      "interaction": "...",
      "members": ["代表作1.md", "代表作2.md"],
      "duplicate_groups": {{
        "代表作1.md": ["同一作者的学位论文版.md"]
      }},
      "flagship": "代表作1.md"
    }}
  ]
}}

## 归纳原则
1. 按研究思路/方法论的相似性归类，而非按期刊或年份
2. 主题名要通俗白话，一看就懂
3. 每个主题必须有理论解释（不能省略）
4. 每篇文献必须且只能归入一个主题
5. 不要在 JSON 里出现任何实证结果的具体系数或显著性数字
6. members 列表必须使用下方提供的精确文件名
7. flagship 必须是 members 列表中的某一个文件名（不能是不存在的文件名）
8. **避免单主题过大**：单个主题涉及的文献不要太多，否则导览价值下降。如果某个主题下文献数量明显多于其他主题，应进一步按方法论维度合理细分（如「同一类相关性度量」可按数据频率/识别策略/样本市场等子维度细分），让每个主题保持清晰的方法论边界。

9. **同团队重复发表去重（极重要！）**：在主题内识别「同团队重复发表」，**只在 members 里列代表作**，跟随的重复版本一律放进 duplicate_groups：
   - **典型同团队重复发表模式**：
     * 同一第一作者 + 标题归一化前缀 80% 相同：学位论文 vs 其期刊压缩版、中文版 vs 英文版（中英文双发）、上中下连载拆分发表
     * 核心思路高度重复（70%+ 文字重叠），仅样本区间扩展或稳健性检验增补
   - **代表作选择标准**：
     * 优先选**期刊正式发表版**（学位论文让位期刊版）
     * 若某版本包含明确的方法变体（如更换识别策略、更换代理变量并得到新结论），则它本身就是独立代表作，不算重复
   - **判定标准（满足以下任一即归为同一重复组）**：
     * 同一第一作者，标题归一化前缀（去年份/期数/括号/冒号后内容）相同 80% 以上
     * 同一第一作者，核心思路前 200 字 70% 以上文字重叠
     * 同一第一作者，关键创新点描述的"首次"内容几乎一致（仅措辞差异）
   - **不同第一作者的文献永远不算重复**，即使内容相似（不同团队的独立研究有引用价值）
   - **目标**：让 members 里每篇都代表一个真正独立的方法贡献
   - **代码会自动**：从代表作的 individual 摘要抽取关键创新点；为有 duplicates 的代表作输出小注「另有 N 篇同团队重复发表版本：年份列表」

---
以下是所有文献的完整 individual 结构化摘要（每篇含「核心思路」「数据与样本」「模型与方法构建」「理论解释与机制分析」「异质性与边界条件」「关键创新点」六段）：

{all_summaries_text}
```

## 主题归纳的核心原则

1. **按研究思路/方法论的相似性归类**，而非按期刊或年份。思路相似 = 解决同一类问题、用同一大类方法。
2. **主题名要通俗白话** — 不要写"量价相关性的多维度结构化建模与截面定价机制"这种学术腔，要写"用分钟级量价相关系数预测收益"这种一看就懂的。
3. **每个主题必须保留理论解释** — 这是读者理解方法逻辑的关键，绝对不能省略。
4. **无关文献清单仅在 B3 启用时附在末尾**（v1.1 默认停用 B3、无剔除环节，汇总文档不含此节）。
5. **"涉及文献"只摘录关键创新点，必须简短** — 每篇 1-2 句即可。汇总文档是"导览"，不是"全文复读机"——核心思路、详细公式推导都在 individual 摘要里，让读者点进去看。
6. **每个主题只放 1 个 flagship 公式块** — 从 members 中选最具代表性的一篇，由代码从其 individual 摘要的"模型与方法构建"段抽取公式插入文档。不要每篇都铺开公式，避免回到冗余状态。
7. **flagship 选择标准**：开山之作（首次提出）、方法定义最完整、被后续文献反复引用作为基准、或该主题最经典的实现。

## 拼装策略

LLM 只产出 JSON 分组，"涉及文献"列表由代码用正则从 individual 文件抽取关键创新点直接拼进文档。详见 [reference/summary/two_step_strategy.md](../summary/two_step_strategy.md)。

## 输出

- `output/thematic_summary.md` — 最终汇总文档
